# FullUI API contract (all routes under `/FullUI`, JSON camelCase, auth = normal Jellyfin token)

DTOs: `server/Jellyfin.Plugin.FullUI/Api/Dtos.cs`. Storage model: `Data/Models.cs` (PluginStore). Library snapshot: `Library/CatalogItem.cs` (ICatalog).
User id inside controllers: `User.FindFirst("Jellyfin-UserId")` (a Guid). Admin endpoints: `[Authorize(Policy = "RequiresElevation")]`. Never take a user id from the client.

**JSON casing.** Jellyfin's own MVC formatter is PascalCase, so every FullUI action serializes explicitly through `SafeApi.Json` (camelCase) - including the Admin routes, the `Tmdb/Test` and `Ollama/Test` buttons and all error bodies. A test renders every action through an MVC pipeline configured like Jellyfin's and fails on any capitalised key. Request bodies are read case-insensitively. Guids in bodies are written in the default dashed form.

| Route | Purpose |
|---|---|
| GET `Home` | `HomeResponse` (rows in display order; `comingsoon` row carries `comingSoon[]`, others `items[]`). Row ids are unique (clients key lists on them). **5xx** (problem body) when the home cannot be built; an empty `rows` array with 200 means a genuinely empty library, never a failure |
| POST `Rate` `{itemId, rating}` | rating -1/0/1/2 (0 clears). 2 (love) also sets Jellyfin favorite. Invalidates user's home cache. 404 when the user cannot see the item |
| POST `MyList` `{itemId, add}` | add/remove from My List. 404 when the user cannot see the item |
| GET `Item/{id}` | `ItemCard` for one title (More Info), including resume `progress`. 404 when missing or not visible |
| GET `MyServer` | `{ continueWatching: ItemCard[], myList: ItemCard[], wanted: ComingSoonCard[] }` (5xx on failure, like `Home`) |
| GET `ComingSoon` | `{ cards: ComingSoonCard[], recommended?: ComingSoonCard[] }` for the current user (empty when TMDB key unset). `cards` are **true Coming Soon titles only**: release date (movies) or first air date (shows) is **today or later**, or a new season whose first episode has not aired. Same cards as the Home row: titles already in the library are dropped (a new season of a show you have is kept), "not for me" titles stay hidden. `recommended` (omitted when the admin turned `ShowRecommendedNotInLibrary` off or TMDB is unset) is the separate "Recommended for you (not in library)" list: already-released titles users can still request/vote for |
| POST `Vote` `{tmdbId, mediaType, vote, title,...}` | vote 1 = I want this, -1 = not for me, 0 = clear. At most 500 votes per user (400 `{message}` beyond that; changing or clearing is always allowed) |
| GET `Search?q=` | `SearchResponse` `{mode, items}` (mode `semantic` when Ollama is enabled and reachable, else `keyword`). Cards carry badges and trailer keys like Home cards. With Ollama on, titles that have no usable vector yet are still found by name |
| GET `Notifications` / POST `Notifications/Read` | in-UI bell. `{items: NotificationDto[]}` / `MarkReadRequest {ids?: guid[]}`. **A missing body, `ids: null` or `ids: []` marks ALL of the caller's notifications read**; a non-empty list marks only those. Notifications older than 90 days (and beyond the newest 200 per user) are pruned |
| GET `Status` | `{serverName, accentColor, tmdbConfigured, ollamaEnabled, trailersEnabled, webInjected, playerAssistEnabled, collectMetrics, tmdbAttribution, tmdbAttributionText}` for a **signed-in** user (`[Authorize]`; it is NOT public, so clients must not call it on the login page). `accentColor` is always a valid `#hex` (invalid admin input falls back to `#e5383b`). Never contains the TMDB key |
| POST `Tmdb/Test`, POST `Ollama/Test` | admin settings page buttons; body `{ok, message}` (200 even when the test fails; `ok=false` carries the reason) |
| GET `Admin/Requests?sort=votes\|recent` | admin: aggregated requests `[{tmdbId, mediaType, title, posterPath, releaseDate, wantCount, voters[], status, note, tmdbUrl, lastVoteAt}]` |
| POST `Admin/Requests/Status` `{tmdbId, mediaType, status, note}` | status: Requested, Getting it, Added |
| GET `Admin/Requests.csv` | CSV export, UTF-8 **with byte order mark** (Excel shows accents correctly) |
| POST `Admin/Rebuild` | admin: rebuild caches now (202, runs in the background) |
| GET `Admin/Injection` | admin: `{registered, attempts, message}` - whether the reskin is hooked into the Jellyfin web page (via the File Transformation plugin). The settings page shows `message` in plain English |
| POST `Remind` `{tmdbId, mediaType, on}` | Remind me for a Coming Soon title (`on:false` clears). 204. 400 `{message}` when the title is not on the caller's own Coming Soon/vote lists, or at 200 reminders. On the release day (daily task, 06:00) the caller gets a bell notification "X is out today"; when the title shows up in the library (and is visible to them) "X is now on {server}". Each reminder fires once. Private: only the caller's own |
| GET `Reminders` | `{ items: [{tmdbId, mediaType, title, posterPath, releaseDate, seasonNumber, notified}] }` the caller's own reminders, soonest first |
| GET `NewPopular` | `{ comingSoon: ComingSoonCard[], everyonesWatching: ItemCard[], top10Movies: ItemCard[], top10Shows: ItemCard[] }`. `comingSoon` is upcoming-only and **sorted ascending by `releaseDate`** (group by date in the client), each card has `upcoming:true` and `reminded`. The three item lists come from `ITrendingProvider`: by default `EngineTrendingProvider`, i.e. the recommendation engine's own `trending`, `top10-movies` and `top10-shows` rows for this user (the same lists as on Home: visible, not thumbed down, not finished or dropped, kids and `ExcludedUserIds` left out of the shared signals, duplicate editions merged). When the engine throws, or has no such row (household too small for a chart), the signal-only `SignalTrendingProvider` answers instead (recent play signals, visible titles, not thumbed down). Top-10 cards carry `rank` (position in the list) |
| POST `Events` `{events:[{type, rowType?, itemId?, query?, at?}]}` | impression/interaction log. `type` in `rowShown, cardExpanded, cardClicked, playStarted, trailerViewed, searchIssued, searchClicked`. Max **200** events per call (400 beyond), max about 1000 events per user per minute (429 + `Retry-After`). `rowType` is the row type id (`[a-z0-9_-]`, max 40), `itemId` a title id, `query` max 100 chars, `at` an ISO string or epoch ms (replaced by server time when out of range). The user comes from the token only. Response `{accepted, rejected}`; when the admin switched collection off (`collectMetrics:false` in `Status`) it answers 200 `{accepted:0}` and stores nothing. Stored in `fullui/events.jsonl` (rotates at 10 MB, one old file kept, lines older than 90 days removed daily). **`playStarted`** is sent by the page when it starts playback from a card (with its `rowType`); independently the **server** records a `serverPlayStarted` event (no row, never accepted from clients) for every Movie or Episode (stored against the series; specials skipped) that Jellyfin reports as started (`ISessionManager.PlaybackStart`), whatever app started it, unless `collectMetrics` is off. In `Admin/Metrics`, `playsTotal` is the number of server-recorded starts (falling back to the page's own `playStarted` count when the server has recorded none yet, never lower than it), `playsFromRows` the page's `playStarted` events that carried a `rowType`: the pair is the numerator and denominator of "how many plays did FullUI's rows cause" |
| GET `Onboarding` (`?force=true`) | `{ eligible, items: ItemCard[~24], genres: string[] }`. `eligible` is true only for a user who has not finished onboarding and has fewer than 5 titles of history; otherwise `items`/`genres` are empty unless the user re-opens the picker on purpose with `force=true`. Items are visible, rated 6.5+, spread round-robin over genres and over movies/shows, and exclude titles the user already has a signal for |
| POST `Onboarding` `{liked:[itemId], genres:[name], skipped}` | every visible, not yet rated `liked` title becomes rating +1, `genres` (library spelling, unknown ones dropped) are stored as the user's genre preferences, onboarding is marked done (a skip only marks it done). Ids may be dashed or not. Response `{seeded, genres, skipped}`; the user's Home cache is invalidated |
| POST `ContinueWatching/Hide` `{itemId}`, POST `ContinueWatching/Unhide` `{itemId}` | per-user hide of a title from Continue Watching (204; 404 when the title is not visible to the caller; at most 1000 per user). The engine reads it through `IHiddenItems` |
| GET `Search/Suggest?q=` | typeahead `{ titles:[{id,name,year,type}], people:[{name,titles,itemIds}], genres:[string] }`; visible titles only; typo tolerant (swapped/missing letters, trigram similarity); `people` stays empty until the catalog exposes cast (`ICastIndex`). `GET Search` additionally appends titles of a matching person and, when nothing matched, close-typo titles |
| GET `Admin/Metrics` (`?days=30`) | admin: aggregates only, never per-user events: `{collecting, windowDays, totalEvents, activeUsers, rows:[{rowType, shown, clicks, plays, expanded, takeRate, playsPerShown}], neverClickedRows, playsFromRows, playsTotal, topSearches:[{query,count,users}], eventsPerDay:[{day,events}]}`. `takeRate = (clicks+plays)/shown`. `playsTotal` counts every playback start the server saw (see `Events`), `playsFromRows` those that came from a FullUI row; `totalEvents`/`activeUsers`/`eventsPerDay` include the server's own `serverPlayStarted` events |
| GET `Admin/Health` | admin: `{overall: ok / attention / problem, summary, pluginVersion, supportedJellyfin:"10.11.6 and later", storeFormat, injection, tmdb, ollama (each {enabled,status,color,message}), catalogItems, tasks:[{key,name,lastStartUtc,lastEndUtc,outcome,color,status,message}], files:[{name,bytes,count}], counts, recentErrors:[{at,message}], generatedAt}`. `color` is green / amber / red / grey. Never contains keys, URLs or paths (messages are scrubbed). Shown by the "FullUI Health" admin page |
| GET `Admin/Export` (`?user=<id>`) | admin: JSON file download `fullui-export-YYYY-MM-DD.json` (`{format:"fullui-export", version:1, exportedAt, users:{<userId N>:{name, ratings, myList, votes, notifications, reminders, onboarding, hiddenContinue}}, statuses}`), everything or one user. `statuses` only in a full export |
| POST `Admin/Import` (`?dryRun=true` is the default) | admin: body is an export document (max 20 MB). Strict: wrong format/version, more than 500 users or absurd sizes answer 400 `{valid:false, message}`; unknown users, titles not in this library and invalid values are skipped and listed in `skipped`. Response `{dryRun, valid, message, users, ratings, myList, votes, notifications, reminders, onboarding, hidden, requests, skipped[]}`. Nothing is written unless `dryRun=false`; importing the same file again changes nothing |
| POST `Admin/Purge` `{userId: <id> or "all", confirm?}` | admin "delete my data" / uninstall clean-up. The first call (no `confirm`) deletes nothing and returns `{confirmRequired:true, token, expiresInSeconds:300, summary}`; send the token back as `confirm` (single use, same target) to delete. A user purge removes that user's signals, ratings, My List, votes, notifications, reminders, Coming Soon list, onboarding, hidden titles and usage events; `all` also clears request statuses, trailer keys, row titles, the AI index and the usage log |
| GET `web/fullui.js`, `web/fullui.css`, `web/tmdb-logo.svg` | anonymous static bundle. `Cache-Control: no-cache` + `ETag`: browsers revalidate and get 304 when unchanged |

**Errors.** 4xx validation errors from FullUI endpoints are `{ "message": "..." }`; unexpected failures are 500 with the same shape (`SafeApi`) or, on the Home/Rate/MyList/Item/MyServer routes, an RFC 7807 problem (`{type?, title, status, detail}`, `application/problem+json`). Neither ever contains exception text, paths, URLs or keys; details go to the server log. Clients should key on the HTTP status and show their own friendly text.

**ItemCard** extras: `imageTag` (optional string) is a short token that changes when the item's primary image changes; clients add `&tag={imageTag}` to `/Items/{id}/Images/...` URLs so images can be cached for a long time. `badges`, `trailerKey`, `progress`, `rank` as before.

**ComingSoonCard** extras (added at the end, optional for clients): `upcoming` (bool, the release date is today or later) and `reminded` (bool, the caller set Remind me). Existing fields are unchanged.

**TMDB attribution.** Wherever TMDB data or images are shown, a page must display the TMDB logo (served locally from `GET web/tmdb-logo.svg`, no hotlink) and the sentence in `Status.tmdbAttributionText` ("This product uses the TMDB API but is not endorsed or certified by TMDB."). The admin pages (settings, requests, health) already do.

**Top 10 titles** follow the `TopTenWindowDays` setting: 7 days = "Top 10 Movies on {Server} This Week", 1 = "... Today", otherwise "... in the Last N Days".

**Home composition notes.** Continue Watching also lists a series whose latest episode was finished when Jellyfin's Next Up has another episode ready (progress `null`). On first start the plugin imports existing Jellyfin watch history (played, resume points, favorites -> Love) once per user, so Home is not cold. The per-user "visible titles" list (the privacy filter behind every row, search, rating and My List) is cached for 2 minutes; permission or parental-rating changes in Jellyfin take at most that long to apply. Fails closed: if the list cannot be read, nothing is shown.

Images (client side): `/Items/{id}/Images/Primary|Backdrop|Logo?maxWidth=...`; TMDB posters `https://image.tmdb.org/t/p/w342{path}`.
Trailers: `trailerKey` is a YouTube video id.
Rows order (server decides): continue, toppicks, top10(movies), collection x0-2 (`collection-{id}`, "Next in {BoxSet}"), because x3, trending, comingsoon, mylist, genre x3, top10(shows), newseasons, recent, hidden, again.

**Recommendation notes.** Every row passes one eligibility rule: titles the user thumbed down, hid, finished (except in Watch Again), dropped (a show they started and abandoned) or cannot see never appear. A series counts as finished only when the user has watched every episode; one finished episode no longer marks the whole show. `newseasons` ("New Episodes") lists followed shows with a genuinely new season or new episodes since the user last caught up. Recommendation rows (toppicks, because, genre, hidden, collection) never share a title; Trending, charts, Continue, My List, Recently Added and Watch Again are exempt. Minimum row size shrinks from 5 to 3 for small libraries. Duplicate editions (same TMDB id) collapse to one card. Cards carry `matchPercent` (1-99, null on cold start), `reason` (plain English), and for Continue Watching `seriesLabel` ("S2:E5") and `minutesLeft`. Users with a restrictive parental cap (heuristic: they see none of the library's mature-rated titles) are left out of Top 10, Trending and collaborative filtering when `ExcludeKidsFromSharedSignals` is on.
Vote privacy: users only ever see their own votes; only admin endpoints expose totals/voters.

## Server notes

- **Hooking into the web page** is done by a hosted service after Jellyfin starts (not while services are registered: File Transformation is not constructed yet at that point). It retries a few times over about 15 minutes and logs each outcome (`FullUI: web interface hooked in ...` / `... NOT active ...`). The injected tags use page-relative URLs (`../FullUI/web/fullui.js`), so a Jellyfin Base URL or reverse-proxy sub-path works.
- **Scheduled tasks** are found by Jellyfin's assembly scan; they are intentionally not also registered in DI.
- **Jellyfin.Controller** is pinned to `10.11.6` (the oldest supported server) and `tools/abi-matrix.sh` proves every referenced Jellyfin member exists unchanged in 10.11.6 to 10.11.11. See `.claude/skills/jellyfin-version-compat`.
- **Storage**: `fullui/store.json` (small; carries `Version`, currently 2: files without it are version 1 and are upgraded in memory by `Data/StoreMigrations`, a `store.json.v1.bak` copy is kept the first time, and a file from a newer FullUI is backed up and read as far as understood), `fullui/embeddings.json` (AI vectors, loaded on first use) and `fullui/events.jsonl` (+ `events.1.jsonl`, the usage log, bounded to about 20 MB / 90 days and kept apart from the store). Saves are debounced (5 s after the first unsaved change), written atomically, and never block readers while serializing. A corrupt file is kept as `.bad` and the plugin starts empty.
- **Scheduled tasks and history.** Besides the earlier tasks there is "FullUI: Send reminders and tidy up" (`FullUIDaily`, 06:00). `TaskRunRecorderService` listens to Jellyfin's task manager and keeps the last 20 runs per FullUI task in the store (`TaskRuns`) for the health page; any component (including the engine) can also call `ITaskRunLog.Record/Note`. The long-running background services report too, so the health page is complete: "Learn from playback" (`EventTracker`, key `FullUIPlaybackTracking`, recorded at startup: Success when it is listening to Jellyfin, Failed when the subscription failed) and "Import existing watch history" (`PlaybackBackfillService`, key `FullUIPlaybackBackfill`, recorded on every run, about every 6 hours: Success with a count or "Nothing new to import.", Problem when some users could not be imported, Failed when the run itself failed). Both always appear in `Admin/Health.tasks` ("Has not run yet" before their first run). The last 50 friendly problem messages are kept in memory (`Ops/ErrorLog`, scrubbed of keys, URLs and paths).
- **Extension points for the recommendation engine** (registered in `FeatureServicesRegistrator` / `DiscoveryServicesRegistrator`): `IHiddenItems` (exclude hidden titles from Continue Watching), `IRowEngagementProvider.GetEngagement(userId)` (row type -> 0..1 smoothed take rate, to order rows per user), `ITrendingProvider` (the New & Popular lists; `EngineTrendingProvider` is the default and `SignalTrendingProvider` its fallback; registered with TryAdd so another implementation wins), `ICastIndex` (people per title for suggestions and search), `IHomeInvalidator`. The ones the engine may replace use `TryAdd`.
- **Parental filtering of titles that are not in the library** (Coming Soon): a user with a Jellyfin parental cap only sees TMDB titles whose certification (movie `release_dates` / tv `content_ratings`, configured region first, then US) is recognised by Jellyfin and not above the cap; no or unknown certification means hidden. Users without a cap are not checked. TMDB is always called with `include_adult=false`, and "upcoming" comes from `/discover` with a date floor of today (never `/tv/on_the_air`).

## Title details (wave 2)

`GET /FullUI/Item/{id}/Details` (user from token; 404 when the title is not visible to the user; 5xx problem body on failure) returns:

```json
{
  "item": { "...ItemCard..." },
  "tagline": "optional string",
  "seasons": [
    { "id": "guid-N", "number": 1, "name": "Season 1", "episodeCount": 10, "watchedCount": 4,
      "episodes": [
        { "id": "guid-N", "number": 1, "name": "Pilot", "overview": "optional", "runtimeMinutes": 47,
          "progress": 0.42, "played": false, "hasImage": true, "airDate": "2024-01-31" }
      ] }
  ],
  "nextUp": { "episodeId": "guid-N", "seasonNumber": 1, "number": 5, "name": "Title", "progress": 0.0 },
  "people": [ { "name": "Jane Doe", "role": "Dr. Smith", "type": "Actor", "id": "guid-N", "hasImage": true } ],
  "trailers": [ { "key": "YouTubeVideoId", "name": "Official Trailer" } ],
  "similar": [ { "...ItemCard..." } ]
}
```

Movies have `seasons: []` and `nextUp: null`. Season 0 (specials) is returned as `number: 0`, always last; episodes are in episode order. `progress` is 0..1 only for a partly watched, not finished episode (else `null`); `watchedCount` counts finished episodes. Everything is for the calling user (Jellyfin's own per-user library access and watch state).

- `nextUp` (series only): the episode Jellyfin's Next Up names; else the partly watched episode; else the first unwatched regular episode; `null` when everything is watched. Specials never count.
- `people`: at most 20, actors first (billing order, at most 14), then directors (3) and writers (3). `id` is the person's Jellyfin id and may be `null`; `hasImage` is only true when `id` is set. Image: `/Items/{id}/Images/Primary`.
- `trailers`: at most 5 YouTube ids: Jellyfin's own trailer links (with their names), the library snapshot's trailer, then, when a TMDB key is configured, the keys the nightly TMDB task cached (Trailer/Teaser clips only). **No network call is made on the request path.** `name` is "Trailer" when unknown.
- `similar`: at most 12 cards ("More like this"): the engine's neighbours by content (genre, cast, studio, tags), AI embeddings when present, and the other members of the title's collection (first, `reason` "Also in {collection}"; otherwise `reason` "Similar to {title}"), with `matchPercent`. They pass the same eligibility rule as every row: visible to the user, not thumbed down, not finished, not a dropped show; never the title itself or a duplicate edition of it. If this part fails the rest of the page still opens with `similar: []`.
- Errors: **404** when the title does not exist or the user may not see it (a title the user removed from Continue Watching still opens); **401** without a user; **500** as an RFC 7807 problem body when Jellyfin cannot be read (no exception text).
- Images: `/Items/{id}/Images/Primary` for episodes and people. Camel-case JSON via `SafeApi.Json`; ids are `Guid.ToString("N")`. Nothing user-specific is cached beyond the existing 30 s home cache the card is read from.

## Contract fixtures

`docs/contract-fixtures/*.json` are real serialized responses produced by the server code (`ApiTests/ContractFixtureTests`: real controllers and services over a fixed household and clock, serialized through `SafeApi.Json`). The test fails when a committed copy differs from what the code produces; set `FULLUI_UPDATE_FIXTURES=1` to rewrite them. The web mocks and TypeScript types must be built from these files, never hand-written. `docs/contract-fixtures/README.md` lists the file for every route (Status, Home, MyServer, Item, Item Details for a series and a movie, ComingSoon, NewPopular, Reminders, Onboarding, Search keyword/semantic, Search/Suggest, Notifications, Events request/response, Admin/Metrics, Admin/Health and the four error shapes).
